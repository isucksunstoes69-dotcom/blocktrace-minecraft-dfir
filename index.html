06 / GUIDE NOTES

How to use this guide

READ → RECORD → CORRELATE

Start by establishing whether the environment can be trusted. Then build an execution timeline, inspect the client and mods, test specific hypotheses, and only use live-memory review when the earlier evidence supports it.

01

Anti-forensic / bypass detection

Run first. Registry, event-log, hosts, policy, and USN-journal findings tell you whether later artifacts may have been changed or hidden. During an active review, document findings before choosing any remediation.

MeowResolver · FilelessBypassDetection
02

Artifact parsers

Build the execution timeline with Prefetch, BAM, UserAssist, Amcache, USN Journal, and USB history. Cross-check missing paths, signatures, timestamps, renames, and deletion traces rather than relying on a single signal.

PrefetchView · BAMReveal · JournalParser · USBDetector
03

Client / mod scanners

Identify what was actually loaded. Review mods and jars for provenance, obfuscation, suspicious APIs, known module names, and relevant strings. Capture the path, hash, and exact finding for each lead.

MeowModAnalyzer · zeezyparser · StringsParser
04

Client-specific detectors

Use focused detectors to confirm or rule out a concrete hypothesis after collecting historical artifact evidence. Treat hits as leads that need independent corroboration.

MeowClientFucker · MeowDoomsdayFucker · MeowNovowareFucker
05

Memory scans

Use last. Live-memory review is invasive and slow, so reserve it for cases where the prior timeline, mod review, or client-specific indicators provide a reason to check what is currently loaded.

KernelLiveDumpTool · Velociraptor
◆

Record a defensible result

For every conclusion, retain the artifact source, UTC timestamp, file path, hash, tool version, rule or indicator name, and at least one corroborating signal. A single detection is a lead; correlation is the finding.
